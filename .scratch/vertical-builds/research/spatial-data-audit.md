# Spatial data audit: parser, payload, 2D map

Survey date: 2026-11-23. Ticket: [Spatial data audit](../issues/31-spatial-data-audit.md).

Checkout `6b1acda` on `update/upstream-v0.2.2`. Fork PR [#6](https://github.com/avmantonio/satisfactorymap-verticalbuild/pull/6) merged upstream v0.2.2 as `4327b3b` (“Merge upstream v0.2.2 into the Height-view fork”). This tree is that merge plus `4637ecd` (PostHog off), `bc019aa` (edit baseline), and `6b1acda` (a vanilla body that will not parse fails the load; a mod class still skips). PR #6 did not add a coordinate or orientation field. It changed what survives a bad body: mod trailing bytes stay opaque, an unreadable mod object is reported, and a building point still comes from the actor header. `6b1acda` then makes an unreadable *vanilla* body fatal. Diff of the spatial sources against pre-merge `493a3ce` touches `object.rs`, `store.rs`, `extract.rs`, `mapdata/{mod,index,queries,scan,describe}.rs`, and `data.js`. `filters.js`, `webgl_layer.js`, `map.js`, `save_client.js`, and `altitude.js` are unchanged by that range.

`game_data/generated/` is not on disk in this checkout (no files under that tree on 2026-11-23). Sizes below are the extractor and `geometry.rs` contract, not a class count.

The 4 m figure in `height_view.js` is the cut’s stand-in when a table height is missing. It is not a measured size and it is not a row in the matrix.

## Gist

The save already has, per actor, a type path and a 40-byte transform: quaternion, position in centimeters, scale (`level.rs` 38–45). Lightweight buildables repeat quaternion and position as doubles and then throw scale away (`object.rs` 301–308). The map payload is JSON, not a spatial binary. It ships map pixels, a yaw (or a flat tilted hull), and altitude in meters. Full quaternion, roll, scale, and spline tangent Z are dropped before the client. Plan size and `heightExtentM` are a class lookup in `buildings.json`, a labeled reserve, not a per-instance shell. A point in 3D can be placed from the current buckets by inverting pixels and reading z. A box needs the class lookup, and a miss means the point plus an unknown size. A path’s samples are on the payload; the vertical tangent is not.

## What the parser keeps

Actor headers are read before the body. `needTransform` is stored (`store.rs` 26, `level.rs` 30) and never read again. The next 40 bytes are four `f32` rotation components, three `f32` position components, three `f32` scale components (`level.rs` 38–45, `store.rs` 27–29). Editor yaw composition treats that quaternion as x, y, z, w (`editor/apply.rs` 289). Position units on the wire of the save are the engine’s centimeters (`geometry.rs` 22, `world_z_to_meters` 57–59).

A component header has class name, root, instance name, and parent actor. It has no transform (`store.rs` 36–42).

Lightweight instances store rotation `[f64; 4]` and position `[f64; 3]` (`store.rs` 205–207, `object.rs` 301–302). The next three doubles are scale. The comment says vanilla writes unit scale, scaling mods write other values, and nothing downstream reads them; the parser discards the three values (`object.rs` 303–308). `pattern_rotation` is a `u8` paint field (`object.rs` 322), not the actor orientation.

Conveyor-chain actors store, per belt, contiguous 72-byte records of three world-space `f64` triples (`store.rs` 243–250, `object.rs` 413–423). The editor patches those bytes when a chained belt moves (`editor/apply.rs` 449–455, 580–593). The map collectors do not read them.

Spline properties are actor-local `Location`, `ArriveTangent`, and `LeaveTangent` vectors (`extract.rs` 333–341). `vector_prop` returns three components (`extract.rs` 293–297). The collector rotates them by the actor quaternion, projects XY into map pixels, and keeps only the world Z of the location, in meters (`extract.rs` 361–382).

A body that parses and then has leftover bytes is split by class. A vanilla class with leftover bytes is an error (`object.rs` 520–528). A mod class’s leftover is `ActorSpecific::RawBytes` (`object.rs` 530–536), so the property list already parsed — including a spline — stays. Five named mod classes take that raw branch on purpose (`object.rs` 92–98, 466–468). If `parse_object` returns `Err`, `SaveScan::parse_object` records the failure and yields `None` (`scan.rs` 209–216). On this checkout a vanilla class in that set fails the load (`scan.rs` 87–98, `mapdata/mod.rs` 337–338). A mod class is skipped and listed (`mapdata/mod.rs` 331–335, 350–368). `collect_buildings` never calls `parse_object`; it copies the header (`buildings.rs` 150–158). The load-status line says those buildables still draw, without contents (`data.js` 20–33).

## What the payload ships

`build_all_json` writes one JSON object (`mapdata/mod.rs` 312–347). The client decodes those bytes with `JSON.parse` (`save_client.js` 367–370). Tauri may pull the same JSON in slices (`save_client.js` 286–291). The worker’s CBOR blob is the save index handed between wasm instances (`index.rs` 237–246), not the document the map draws.

`slim_payload_value` deletes every `worldPositions` key (`mapdata/mod.rs` 215–224). `jnum` rounds finite floats to two decimal places (`jsonval.rs` 7–16). The comment there says 0.01 map pixel is about 1 cm. `filters.js` then copies the arrays into `Float32Array` (`filters.js` 345, 392, 416).

Building buckets (`buildings.rs` 109–113, 210–225):

- `typePath` once per class bucket.
- `points` stride 4: projected x, projected y, yaw, z meters.
- `footprintPixels`: `[halfWidthPx, halfDepthPx]`, or null.
- `tiltedFootprints`: sparse index → flat pixel polygon, or null.
- `heightExtentM`: `[z0, z1]` meters relative to the actor origin, omitted when the table has neither clearance Z nor a non-zero `dimensions.Height`.
- `renderType`: `"rect"` when a footprint exists, otherwise `"circle"`.

Yaw is `yaw_from_quaternion` (`geometry.rs` 71–74). When tilt intensity `qx²+qy²` is above `0.001` and half extents exist, the bucket stores yaw `0` and a convex hull of the eight rotated corners, projected to pixels (`geometry.rs` 86–92, 129–170, 490–495). Adaptive beams always take that polygon path; length is `BeamLength` in centimeters from the instance, or the table default (`geometry.rs` 470–488, `buildings.rs` 44–46, 184). The length number itself is not a payload field.

Line buckets (`lines.rs` 23–33, 199–208, 235–245):

- Belts, pipes, hypertubes, railroad tracks, and vehicle paths: `pointStride` 7, `[px, py, arriveX, arriveY, leaveX, leaveY, zMeters]` (`extract.rs` 300–304).
- Power lines: `pointStride` 3, straight `[px, py, zMeters]` through the actor and each `Locations` vector (`lines.rs` 136–195).

Belts are `mSplineData` on the belt type paths, with `ConveyorLift` removed (`consts.rs` 109–117, `lines.rs` 235–237). Pipes use the four pipeline classes (`consts.rs` 10–15). Railroads and hypertubes use `mSplineData` (`lines.rs` 207–208). Vehicle paths use `mSplinePoints` on five path classes (`consts.rs` 37–43, `lines.rs` 244–245). A spline with fewer than two points is omitted (`extract.rs` 358–359). If `mSplineData` is absent, `mTopTransform.Translation` becomes a two-point segment (`extract.rs` 346–354). That fallback runs only for type paths passed into `spline_polylines`, so it does not run for lifts.

Vehicles (`simple.rs` 507–528) and train cars (`trains_progression.rs` 178–199) use the same stride-4 point as buildings, with `rendered_yaw`. Train pins are stride 3 at the lead car (`trains_progression.rs` 187–198). `carFootprintPixels` is the locomotive’s curated plan (`trains_progression.rs` 207–209, `consts.rs` 79). Players and the HUB pin are stride 3, no yaw (`simple.rs` 26–49). Resource nodes, collectables, and hard drives are the same stride-3 pattern (`world.rs` 230–232, 285–287, 450–452, 606–608). Creature spawners are not save actors; their positions come from `creatureSpawners.json` (`simple.rs` 98–136).

`describe_instance` is a separate query. For an actor it returns `typePath` and header position in centimeters, rounded by `jnum`, and no rotation (`describe.rs` 133–192). Lightweight lookups return position only (`describe.rs` 141–147). Train-car quaternions sit on `TrainCar.rotation` inside the worker index and in `MapIndex::dump` (`index.rs` 56–57, 435–439, 693–706). `collect_trains` does not copy them onto the map payload.

## What the 2D map drops

- The quaternion. Rects rotate by the stored yaw (`map.js` 19). Icon pins that share a stride-4 array skip the yaw column (`filters.js` 387–390).
- Tilt and roll as angles. A tilted instance is a flat polygon already in map pixels (`filters.js` 350–355). The 2D layer translates that polygon; it does not tilt a volume (`webgl_layer.js` 168–175, 1290).
- Scale. No bucket field.
- Tangent Z. Stride 7 carries XY tangents only (`map.js` 22–26, `filters.js` 409–414). The WebGL curve uses those XY components (`webgl_layer.js` 470–471). `height_view.js` 171–173 states the payload has no Z tangent, so Z between vertices is linear.
- Raw world XY. The map addresses Leaflet as `L.latLng(py, px)` under `L.CRS.Simple` (`map.js` 5–10, 2285–2286). z is altitude in meters and is always last in the stride (`map.js` 28–30).
- Vertical extent on the plan. `heightExtentM` is copied onto the building bucket (`filters.js` 1583–1584 and consumed by the cut (`height_view.js` 14–15, 158–163). The 2D layer does not extrude it. `altitude.js` only scans min/max z for the rail filter (`altitude.js` 76–100).
- Per-instance shell. A missing footprint is a circle (`buildings.rs` 218).
- Any actor no collector emits, and any spline whose body will not re-parse (`extract.rs` 331).

## Point, box, path

**Enough to place a point.** Buildings, vehicles, train cars, players, the HUB, resources, and each path vertex already have projected XY and z meters. World centimeters in X and Y come back from `mapPxToWorldXY` (`editor.js` 14–30), which inverts `project_xy` (`geometry.rs` 49–54). z on the payload is already meters. That places the sample. It does not orient it.

**Missing for a box.** Yaw is on stride-4 rects, so a plan rectangle can be turned. The vertical size is `heightExtentM` when the class lookup hits, and that value is a floored clearance union or `dimensions.Height`, not the mesh (`geometry.rs` 402–442). XY half-extents are the same tables, in pixels (`geometry.rs` 445–458). A class with no table size, no curated pair, and no `ConveyorLift` substring has no dimensions (`buildings.rs` 218). The mark is the point. Vehicle plan sizes are a hardcoded list with no height (`consts.rs` 69–80). Quaternion and scale are not on the payload, so a tilted or scaled box cannot be rebuilt from the buckets. The tilted hull is a plan silhouette.

**Missing for a path.** Sample positions and XY Hermite tangents are on the payload for belts, pipes, hypertubes, tracks, and vehicle paths. Tangent Z is not, so a rise between samples is a straight blend of vertex z. Power wires have no tangents at all (`lines.rs` 195). The chain actor’s world-space triples are a second copy on the save, used by the editor, not shipped. A vehicle or train actor is a posed point; its route is the separate path or track polyline. Nothing in the payload attaches the actor to a distance along that curve. Conveyor lifts are excluded from the belt path list (`consts.rs` 116–117) and are placed as buildings.

## Uncertainties

- `needTransform` is stored and never consulted (`store.rs` 26). This pass did not check a save where the flag is false, so it is unverified whether those 40 bytes are still a real pose.
- Conveyor-lift length is not read by any map collector (`consts.rs` 116–117 removes lifts from belt paths; `mTopTransform` is only the spline fallback in `extract.rs` 346–354). The property name that holds a lift’s travel, if the save has one, was not confirmed by opening a lift actor.
- Whether chained belts still carry a full `mSplineData` on the belt actor, or only the chain actor’s 72-byte elements, was not checked against a 1.0 save. The map path is whatever `spline_polylines` finds on `mSplineData`. The chain elements are parsed either way and are not shipped.
- `game_data/generated/` is absent here, so this note does not say how many classes have clearance, height, or neither. `sav_core` embeds `generated/docs/buildings.json` with `include_str!` (`gamedata/mod.rs` 192) and does not compile until that file exists. The shape is `SCHEMA.md` 148–222 and `extract_docs_json.py` `extractDimensions` 179–190.
- `MapIndex::to_cbor` (`index.rs` 246) was not dumped. Train-car quaternions are fields on `TrainCar`, and `dump()` emits them. The map page does not read that index; the payload it does read has yaw only.
